1. EXECUTIVE SUMMARY & PARADIGM SHIFT

1.1 The Failure of Probabilistic Scanning Architecture

Standard low-cost hazard scouting prototypes (including legacy systems relying on simple Ultrasonic and Infrared sensors) suffer from a fundamental flaw: Acoustic and Spatial Ambiguity. Ultrasonic sensors emit wide, blurry cones that cannot detect diagonal hazards or narrow obstacles. This results in the software outputting only a statistical guess of obstacle presence.

For tactical first responders, bomb disposal technicians, and defense personnel, a statistical guess is useless—they require high-fidelity spatial verification to confirm a safe path or identify hidden physical components before human entry. Commercial defense-grade LiDAR robots achieve this fidelity but cost upwards of ₹50 Lakhs to ₹80 Lakhs.

1.2 The TRISHUL Deterministic Solution

Project TRISHUL replaces statistical estimation with a Frugal Swept Solid-State LiDAR Engine. The breakthrough architecture involves hooking four VL53L1X high-precision Time-of-Flight (ToF) laser distance sensors to four separate MG90S metal-gear servos—one assembly per quadrant of the robot chassis.

When the UGV stops to perform a scan, the ESP32-S3 executes a synchronous, high-speed swept acquisition, moving the four servos simultaneously in lockstep. This generates a crisp, high-density, $360^\circ$ spatial point cloud around the robot base. Path determination is calculated against a clean deterministic grid of actual physical points, rather than a blurry probability area. This allows TRISHUL to deliver LiDAR functionality for **under ₹6,000**, a $100\times$ cost disruption.

2. APPLIED PHYSICS & APPLIED MATHEMATICS OF THE SENSOR PAYLOAD

2.1 Applied Physics: 360-Degree Swept ToF Array Mechanics

VL53L1X Solid-State ToF Physics

Each of the four sensors operates via **Solid-State Time-of-Flight (ToF)** photonics. Hidden inside the $4.9\text{mm}$ package is a **940nm Vertical Cavity Surface Emitting Laser (VCSEL)**. The chip emits a synchronized pulse of invisible laser photons. An integrated array of **Single Photon Avalanche Diodes (SPADs)** acts as a digital photon counter, measuring the exact picosecond latency of the reflected photons.

Unlike broad ultrasonic acoustic cones, the ToF sensor projects a focused infrared beam with a variable, tight Field of View ($\text{FoV}$), allowing it to isolate specific spatial features (such as a concealed weaponized device enclosure) rather than just averaging the area.

Mechanically Swept Lidar Mechanics

To convert this solid-state point sensor into a $360^\circ$ LiDAR, the sensor is mounted to the MG90S servo. By controlling the high-frequency alternating magnetic field in the servo's internal DC motor, the sensor head is swept across a specific $90^\circ$ arc relative to its mount. A full spatial scan splits the workload into four parallel $90^\circ$ sweeps executed synchronously by the microcontroller.

2.2 Applied Mathematics: Spatial Coordinate Transformations

Polar Data Acquisition

Each swept sensor assembly acquisitions data in **Polar Coordinates $(r, \theta)$**. The sensor returns a direct distance measurement ($r$) to the obstacle at a specific global sweep angle ($\theta_{\text{global}}$). The global angle must compensate for the robot's heading and the sensor's mounting offset on the chassis:

$$\theta_{\text{global}} = \theta_{\text{robot\_heading}} + \theta_{\text{quadrant\_offset}} + \theta_{\text{servo\_sweep}}$$

Where $\theta_{\text{quadrant\_offset}}$ is Front ($0^\circ$), Right ($90^\circ$), Back ($180^\circ$), or Left ($270^\circ$).

Cartesian Grid Transformation ($x, y$)

To build a flat obstacle map used for point-to-point navigation, the polar data points $(r, \theta)$ are transformed into **Cartesian Coordinates $(x, y)$** relative to the robot's static center point $(0,0)$:

$$x = r \times \cos(\theta_{\text{global}})$$ $$y = r \times \sin(\theta_{\text{global}})$$

By executing this transformation hundreds of times per second across the four parallel swept quadrants, the ESP32-S3 populates a 2D occupancy grid array representing the free and blocked space in the surrounding environment.

3.2 Dual-Core Task Allocation & Memory Math

The ESP32-S3 completely eliminates the problem of **HTTP blocking latency**. Single-core chips like the Arduino Nano pause their main control loop to process incoming network packets, which would crash the robot or miss critical ToF data during a high-speed servo sweep.

FreeRTOS splits the workload on the ESP32-S3:

  • Core 0 (Network Engine): executes the background Wi-Fi stack, processes asynchronous HTTP web dashboard requests from the operator's handheld remote, and broadcasts raw ESP-NOW telemetry packets.
  • Core 1 (High-Speed Control Engine): executes the 4-servo synchronous PWM sweeps, polls the four ToF laser sensors at $100\text{Hz}$, performs the complex $r \cos \theta$ floating-point mathematics, and populates the 2D spatial grid array.

2D Occupancy Grid Memory Footprint

To map a $10\text{ m} \times 10\text{ m}$ room using a standard $10\text{ cm}$ cell resolution, the UGV requires a 2D matrix of $100 \times 100$ bytes. A $100 \times 100$ byte matrix occupies only 10 KB of SRAM. The ESP32-S3 DevKit provides $512\text{ KB}$ SRAM (plus potentially $8\text{ MB}$ PSRAM), making the mapping memory footprint negligible ($< 2\%$) and proving the scalability of this frugal spatial matrix architecture.

4.1 High-current Power Distribution & Noise Mitigation

To make the scan visual and fast, all four servos must move synchronously in lockstep, consuming up to $2.0\text{A}$ of current burst. Drawing this from the ESP32-S3's internal regulator would brown out the microcontroller and reset the entire system. Instead, a dedicated LM2596 switching regulator provides a high-current $5.0\text{V}$ rail for all servos and the ESP32 `VIN` pin. Decoupling ceramic capacitors (Code 104) are placed near the servo power terminal to block high-frequency noise generated by motor brush arcing.

5. DETERMINISTIC CONTROL ENGINE & EMBEDDED SOFTWARE ARCHITECTURE

5.1 The "Scan-On-Demand" State Machine (Core 1)

The core innovation of the Project TRISHUL software architecture is the dedicated **Stop-and-Scan** workflow executed wirelessly on command.

Instead of continuous scanning on the move, a user presses a dedicated **SCAN** button on their handheld remote. This triggers a specific State Machine on the UGV's Core 1 processor:

  1. STAGE 1 [MOTION LOCK]: CORE 1 immediately applies a PWM brake to all four DC geared motors, bringing the chassis coordinate origin $(0,0)$ to a complete, static halt. This eliminates motion-distortion without SLAM.
  2. STAGE 2 [SYNCHRONOUS ACQUISITION]: CORE 1 executes the synchronous swept scan, moving 4 servos simultaneously in $2^\circ$ lockstep while polling the four ToF laser sensors every $25\text{ms}$. Full $360^\circ$ acqusition takes 1.1 seconds.
  3. STAGE 3 [GRID MAPPING]: CORE 1 converts the Polar $(r, \theta)$ points into Cartesian $(x, y)$ coordinates relative to the static robot base. It populates a byte array acting as an **Occupancy Grid Matrix**. Cells identified with an obstacle point are marked `1`; free space cells are marked `0`.
  4. STAGE 4 [WAYPOINT & PATH]: CORE 1 scans the completed byte grid for open corridors and generates the target waypoint coordinates.
  5. STAGE 5 [MOVE-TO-POINT]: The robot exits the scan state and executes the autonomous point-to-point move using the MPU6050 stability vectors for heading guidance.

5.2 Critical Embedded Implementation Code (C++)

#include <Arduino.h>
#include <WiFi.h>
#include <esp_now.h>
#include <Wire.h>

// --- HARDWARE PIN MAPPINGS ---
#define XSHUT_FRONT_LEFT  33
#define XSHUT_FRONT_RIGHT 34
#define XSHUT_REAR_RIGHT  35
#define XSHUT_REAR_LEFT   36

// --- BOOT-STATE ADDRESS ASSIGNMENT ---
// All sensors start at address 0x29. We reassign using XSHUT lines.
void resetToFAddresses() {
  pinMode(XSHUT_FRONT_LEFT, OUTPUT);
  pinMode(XSHUT_FRONT_RIGHT, OUTPUT);
  pinMode(XSHUT_REAR_RIGHT, OUTPUT);
  pinMode(XSHUT_REAR_LEFT, OUTPUT);

  // Pull all XSHUT low to shutdown every sensor
  digitalWrite(XSHUT_FRONT_LEFT, LOW);
  digitalWrite(XSHUT_FRONT_RIGHT, LOW);
  digitalWrite(XSHUT_REAR_RIGHT, LOW);
  digitalWrite(XSHUT_REAR_LEFT, LOW);
  delay(10);

  // Re-enable sensors one-by-one and set new address over I2C
  enableSensorAndSetAddress(XSHUT_FRONT_LEFT,  0x30);
  enableSensorAndSetAddress(XSHUT_FRONT_RIGHT, 0x31);
  enableSensorAndSetAddress(XSHUT_REAR_RIGHT,  0x32);
  enableSensorAndSetAddress(XSHUT_REAR_LEFT,   0x33);
}

// --- SYNCHRONOUS SWEEP & ACQUISITION (CORE 1) ---
// Covers 0 to 90 degrees mechanical servo motion (180 data points)
void executeSynchronousScan() {
  const int SERVO_STEP_DEG = 2; // High-density grid steps
  const int SERVO_SETTLE_MS = 25; // Milliseconds to wait for arm stabilization

  for (int angle = 0; angle <= 90; angle += SERVO_STEP_DEG) {
    // 1. Write PWM to all 4 servos synchronously (lockstep movement)
    servoFrontLeft.write(angle);
    servoFrontRight.write(angle);
    servoRearRight.write(angle);
    servoRearLeft.write(angle);
    
    // 2. Delay for physical mechanical movement
    vTaskDelay(pdMS_TO_TICKS(SERVO_SETTLE_MS));

    // 3. Poll all 4 ToF sensors simultaneously (Parallel acquisition)
    uint16_t dist1 = tofFrontLeft.readRangeSingleMillimeters();
    uint16_t dist2 = tofFrontRight.readRangeSingleMillimeters();
    uint16_t dist3 = tofRearRight.readRangeSingleMillimeters();
    uint16_t dist4 = tofRearLeft.readRangeSingleMillimeters();

    // 4. Store raw polar data into Cartesian conversion logic...
    convertPolarAndStoreGrid(angle, dist1, dist2, dist3, dist4);
  }
}
