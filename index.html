1. EXECUTIVE OVERVIEW: SYSTEM ARCHITECTURE & PROBLEM/SOLUTION FRAMEWORK

1.1 Problem Statement

First responders, hazmat teams, and bomb disposal technicians entering unstructured or hazardous environments face two critical operational failures when deploying conventional low-cost scout rovers:

  • Spatial Blindness: Traditional rovers rely on basic ultrasonic sensors and static infrared beams. Ultrasonic waves bounce off angled walls, creating acoustic echo traps, while IR beams are easily blinded by ambient lighting. The robot cannot construct a usable map of its surroundings.
  • Statistical Gas Ambiguity: Conventional gas scouting relies on analog metal-oxide sensors (like MQ-2 or MQ-135) that output noisy voltage spikes. Software algorithms average these spikes into a vague "percentage risk" score. A false positive can be triggered by humidity, alcohol vapors, or engine exhaust—making statistical scores operationally useless in high-stakes environments.

1.2 The Unified Dual-Core Solution

Project A.R.G.U.S & PRAHARI solves both problems by decoupling spatial mapping from hazard verification into two complementary, deterministic hardware layers:

2.2 Applied Physics & Polar-to-Cartesian Spatial Mathematics

Each of the four VL53L0X purple breakout modules contains a 940nm Vertical Cavity Surface Emitting Laser (VCSEL) and an integrated array of Single Photon Avalanche Diodes (SPADs). The chip measures the exact time taken by emitted photon pulses to bounce off obstacles and return to the receiver.

Polar Data Acquisition

As the four servos sweep synchronously across their respective $90^\circ$ quadrants, distance readings are acquired in Polar Coordinates $(r, \theta)$. The global angle ($\theta_{\text{global}}$) combines the robot's heading, the quadrant offset, and the servo angle:

$$\theta_{\text{global}} = \theta_{\text{robot\_heading}} + \theta_{\text{quadrant\_offset}} + \theta_{\text{servo\_angle}}$$

Cartesian Transformation & Occupancy Grid Mapping

The ESP32-S3 converts polar data $(r, \theta)$ into 2D Cartesian Coordinates $(x, y)$ relative to the robot's center point $(0,0)$:

$$x = r \times \cos(\theta_{\text{global}})$$ $$y = r \times \sin(\theta_{\text{global}})$$

These calculated $(x,y)$ values populate a $100 \times 100$ byte array representing a $10\text{m} \times 10\text{m}$ area at $10\text{cm}$ grid resolution. The entire matrix consumes only 10 KB of SRAM ($<2\%$ of the ESP32-S3's $512\text{KB}$ internal RAM).

2.3 Drivetrain, Electrical Architecture & Single L298N Parallel Motor Math

Electric Math Proof — Why 1x L298N Driver Runs All 4 Motors:
A common misconception is that a 4WD robot requires two L298N drivers. A 4WD skid-steer UGV links the two left motors together and the two right motors together.
  • BO Motor Current Draw: A 100 RPM yellow BO motor draws $\sim 100\text{mA}-200\text{mA}$ operating, with a max stall current of $\sim 800\text{mA}$.
  • Parallel Wiring: Connecting two left motors in parallel to L298N Channel A draws $\sim 400\text{mA}$ running and $\sim 1.6\text{A}$ at absolute stall.
  • L298N Rating: The L298N module is rated for 2.0A continuous and 3.0A peak per channel.
Therefore, one single L298N driver comfortably powers all 4 motors without overheating while saving 6 valuable GPIO pins on the ESP32-S3!

Power Architecture & Voltage Regulation

  • Raw 11.1V Rail: Supplied by a 3-Cell (3S) Pro-Range $11.1\text{V } 1500\text{mAh } 40\text{C}$ LiPo battery pack through a 6A master SPST rocker switch. Feeds the L298N `VMS` motor terminal and the LJ12A3 inductive metal sensor directly.
  • 5.0V Regulated Bus: An LM2596 DC-DC switching buck converter steps the 11.1V battery rail down to a clean 5.0V (3A max). This powers the ESP32-S3 `VIN` pin and the VCC lines of all 4 MG90S servos, preventing motor current spikes from causing microcontroller brownouts.
  • 3.3V Sensor Rail: Provided by the ESP32-S3 onboard LDO, feeding all ToF laser sensors, gas sensors, and IMU modules.

2.4 Handheld Tactical Remote Controller Design

The operator controls A.R.G.U.S using a custom handheld remote powered by an ESP32 NodeMCU-32 (38-Pin) development board. The remote includes:

  • Dual PS2 Joysticks: Joystick 1 controls UGV differential driving speed and steering; Joystick 2 controls pan/tilt functions or manual servo positioning.
  • Action Buttons (3x Red PBS-11B 12mm Buttons): Button 1 triggers the $360^\circ$ "Stop-and-Scan" LiDAR routine; Button 2 toggles threat notification modes; Button 3 resets sensor baselines.
  • 6-Pin Toggle & SPST Rocker Switch: Controls power distribution and wireless transmission modes (ESP-NOW low-latency vs. CC1101 Sub-1GHz NLOS fallback).

3. PART II: THE THREAT VERIFICATION SUBSYSTEM (PRAHARI PAYLOAD NODE)

3.1 Explosive Vapor Chemistry Trap vs. Deterministic Coincidence Matrix

A common misconception in robotics is that a scout rover can detect solid military explosives like RDX, C4, or TNT using cheap gas sensors. In reality, high explosives have an extremely low vapor pressure at room temperature and barely off-gas into open air. Detecting solid RDX directly requires million-dollar mass spectrometers or trained police canines.

However, improvised explosive devices (ANFO, TATP, fertilizer bombs, nitromethane mixes) off-gas volatile organic solvents (VOCs) and nitrogen oxides ($\text{NO}_x$) from precursor instability or chemical degradation. PRAHARI uses a Multi-Modal Hardware Coincidence Matrix to identify these threats deterministically:

$$\text{Verified Threat} = \overbrace{(\text{VOC} > 150 \ \mathbf{OR} \ \text{NO}_x > 150 \ \mathbf{OR} \ [NH_3] > 50\text{ppm})}^{\text{Digital Gas Spectroscopy}} \ \mathbf{AND} \ \overbrace{(\text{Proximity = LOW})}^{\text{Inductive Metal Casing}} \ \mathbf{AND} \ \overbrace{(\Delta T > 15^\circ\text{C})}^{\text{Thermal Anomaly}}$$

3.2 MOx Semiconductor Chemisorption & Inductive Eddy Current Physics

Sensirion SGP41 & DFRobot Fermion $NH_3$ Chemisorption

Both gas sensors utilize Metal-Oxide Semiconductor (MOx) thin films ($\text{SnO}_2$) over an integrated micro-hotplate ($300^\circ\text{C}-400^\circ\text{C}$). Oxygen molecules adsorb onto the surface, extracting conduction electrons and forming an **Electron Depletion Layer ($W_D$)**. When reducing target gas molecules ($NH_3$, VOCs, $NO_x$) hit the surface, they react with oxygen ions, releasing trapped electrons back into the conduction band and causing an exponential drop in resistance ($R_s$):

$$2\text{NH}_3 + 3\text{O}^- \text{ (adsorbed)} \longrightarrow \text{N}_2 + 3\text{H}_2\text{O} + 3e^-$$

The Sensirion SGP41 processes these resistance shifts natively, outputting calibrated digital VOC and $NO_x$ relative index values ($0-500$) over $I^2C$ that ignore ambient temperature and humidity drift.

LJ12A3 Inductive Metal Detection (Eddy Currents)

The LJ12A3-4-Z/BX proximity sensor contains an LC resonant oscillator generating a high-frequency magnetic field ($100\text{kHz}-1\text{MHz}$). When a conductive metallic target enters this field, time-varying flux induces circular **Eddy Currents** inside the metal (**Faraday's Law**). These currents generate an opposing magnetic field (**Lenz's Law**) that saps oscillator energy. An internal Schmitt trigger detects the amplitude drop, flipping an open-collector **NPN BJT transistor** to pull the output line directly to **Ground ($0\text{V}$)**.

6. STEP-BY-STEP HARDWARE ASSEMBLY & WIRING PROTOCOL

Phase 1: UGV Drivetrain & Power Hub

  • Step 1.1: Connect the Pro-Range 11.1V 3S LiPo through the 6A SPST Rocker Switch. Split output into raw 11.1V rail and buck input.
  • Step 1.2: Connect the raw 11.1V rail to the L298N Motor Driver `VMS` terminal and the Brown wire of the **LJ12A3 Proximity Switch**.
  • Step 1.3: Connect 11.1V into the **LM2596 Buck Converter**. Turn potentiometer until `OUT+` reads **5.0V DC**. Route this 5.0V rail to ESP32-S3 `VIN` and VCC of all 4 MG90S Servos.
  • Step 1.4: Solder all ground wires (LiPo (-), LM2596 `OUT-`, L298N `GND`, ESP32 `GND`, and sensor GNDs) to a single Common Ground Bus on a perfboard.

Phase 2: Swept ToF Array & Sensor Installation

  • Step 2.1: Mount one MG90S servo at each chassis corner. Connect servo power to 5.0V rail and signal lines to ESP32-S3 GPIOs 15, 16, 17, and 18.
  • Step 2.2: Secure a purple VL53L0X ToF module to each servo horn. Wire all four ToF `SDA` and `SCL` pins in parallel to ESP32-S3 GPIO 8 and 9. Wire `VCC` to ESP32 3.3V pin.
  • Step 2.3: Wire the `XSHUT` pins of the four ToF sensors to separate ESP32-S3 GPIOs: Front-Left $\rightarrow$ GPIO 33, Front-Right $\rightarrow$ GPIO 34, Rear-Right $\rightarrow$ GPIO 35, Rear-Left $\rightarrow$ GPIO 36.

Phase 3: Threat Payload & Remote Controller Wiring

  • Step 3.1: Connect SGP41 to shared I2C bus (GPIO 8/9). Connect DFRobot $NH_3$ Analog Out to GPIO 4. Connect LJ12A3 Black wire to GPIO 6 (`INPUT_PULLUP`).
  • Step 3.2 (Remote): Wire NodeMCU-32 ESP32 Joysticks (Drive: VRx $\rightarrow$ GPIO 34, VRy $\rightarrow$ GPIO 35; Pan/Tilt: VRx $\rightarrow$ GPIO 32, VRy $\rightarrow$ GPIO 33). Wire PBS-11B Buttons to GPIOs 25, 26, 27 (`INPUT_PULLUP`).

/* 
 * PROJECT A.R.G.U.S & PRAHARI NODE - MASTER UGV FIRMWARE 
 * Platform: ESP32-S3 Dual-Core (FreeRTOS)
 * Sensor Payload: 4x Swept VL53L0X ToF, SGP41 VOC/NOx, DFRobot NH3, LJ12A3 Metal
 */

#include <Arduino.h>
#include <WiFi.h>
#include <esp_now.h>
#include <Wire.h>
#include <ESP32Servo.h>
#include <Adafruit_VL53L0X.h>

// --- HARDWARE PIN DEFINITIONS ---
#define PIN_I2C_SDA 8
#define PIN_I2C_SCL 9

#define XSHUT_FL 33 // ToF Front-Left
#define XSHUT_FR 34 // ToF Front-Right
#define XSHUT_RR 35 // ToF Rear-Right
#define XSHUT_RL 36 // ToF Rear-Left

#define PIN_SRV_FL 15
#define PIN_SRV_FR 16
#define PIN_SRV_RR 17
#define PIN_SRV_RL 18

#define PIN_NH3_ADC 4
#define PIN_METAL_SENS 6
#define PIN_LED_RED 2
#define PIN_LED_GREEN 3

// --- GLOBAL OBJECTS ---
Servo servoFL, servoFR, servoRR, servoRL;
Adafruit_VL53L0X loxFL = Adafruit_VL53L0X();
Adafruit_VL53L0X loxFR = Adafruit_VL53L0X();
Adafruit_VL53L0X loxRR = Adafruit_VL53L0X();
Adafruit_VL53L0X loxRL = Adafruit_VL53L0X();

TaskHandle_t LidarScanTask;
uint8_t occupancyGrid[100][100]; // 10m x 10m at 10cm grid resolution

typedef struct __attribute__((packed)) {
  uint8_t threat_stage;    
  float nh3_ppm;           
  bool metal_present;      
} TelemetryPacket;

TelemetryPacket txData;
uint8_t remoteAddress[] = {0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF};

// --- I2C TOF ADDRESS REASSIGNMENT ---
void initToFSensors() {
  pinMode(XSHUT_FL, OUTPUT); pinMode(XSHUT_FR, OUTPUT);
  pinMode(XSHUT_RR, OUTPUT); pinMode(XSHUT_RL, OUTPUT);

  digitalWrite(XSHUT_FL, LOW); digitalWrite(XSHUT_FR, LOW);
  digitalWrite(XSHUT_RR, LOW); digitalWrite(XSHUT_RL, LOW);
  delay(10);

  // Re-enable and assign unique addresses
  digitalWrite(XSHUT_FL, HIGH); delay(10); loxFL.begin(0x30);
  digitalWrite(XSHUT_FR, HIGH); delay(10); loxFR.begin(0x31);
  digitalWrite(XSHUT_RR, HIGH); delay(10); loxRR.begin(0x32);
  digitalWrite(XSHUT_RL, HIGH); delay(10); loxRL.begin(0x33);
}

// --- CARTESIAN GRID TRANSFORMATION ---
void mapPointToGrid(int distance_mm, float global_angle_deg) {
  if(distance_mm <= 20 || distance_mm > 2000) return; // Out of valid range

  float r_cells = distance_mm / 100.0;
  float rad = global_angle_deg * (PI / 180.0);

  int x = 50 + (int)(r_cells * cos(rad));
  int y = 50 + (int)(r_cells * sin(rad));

  if(x >= 0 && x < 100 && y >= 0 && y < 100) {
    occupancyGrid[x][y] = 1; // Mark obstacle cell
  }
}

// --- CORE 1: SYNCHRONOUS 4-QUADRANT SWEEP ---
void ScanTaskCode(void * pvParameters) {
  for (;;) {
    ulTaskNotifyTake(pdTRUE, portMAX_DELAY); // Wait for remote trigger
    memset(occupancyGrid, 0, sizeof(occupancyGrid));

    const int SERVO_STEP = 2; 
    const int SETTLE_MS = 25; 

    for (int angle = 0; angle <= 90; angle += SERVO_STEP) {
      servoFL.write(angle); servoFR.write(angle);
      servoRR.write(angle); servoRL.write(angle);
      
      vTaskDelay(pdMS_TO_TICKS(SETTLE_MS));

      VL53L0X_RangingMeasurementData_t measure1, measure2, measure3, measure4;
      loxFL.rangingTest(&measure1, false);
      loxFR.rangingTest(&measure2, false);
      loxRR.rangingTest(&measure3, false);
      loxRL.rangingTest(&measure4, false);

      if(measure1.RangeStatus != 4) mapPointToGrid(measure1.RangeMilliMeter, angle + 45);   // FL
      if(measure2.RangeStatus != 4) mapPointToGrid(measure2.RangeMilliMeter, angle + 135);  // FR
      if(measure3.RangeStatus != 4) mapPointToGrid(measure3.RangeMilliMeter, angle + 225);  // RR
      if(measure4.RangeStatus != 4) mapPointToGrid(measure4.RangeMilliMeter, angle + 315);  // RL
    }
    
    servoFL.write(0); servoFR.write(0);
    servoRR.write(0); servoRL.write(0);
    Serial.println("A.R.G.U.S SCAN COMPLETE: Occupancy Grid Updated.");
  }
}

// --- CORE 0: NETWORK & PRAHARI COINCIDENCE LOGIC ---
void setup() {
  Serial.begin(115200);
  Wire.begin(PIN_I2C_SDA, PIN_I2C_SCL);

  pinMode(PIN_METAL_SENS, INPUT_PULLUP);
  pinMode(PIN_LED_RED, OUTPUT);
  pinMode(PIN_LED_GREEN, OUTPUT);

  initToFSensors();
  
  servoFL.attach(PIN_SRV_FL); servoFR.attach(PIN_SRV_FR);
  servoRR.attach(PIN_SRV_RR); servoRL.attach(PIN_SRV_RL);

  xTaskCreatePinnedToCore(ScanTaskCode, "LidarScanTask", 10000, NULL, 1, &LidarScanTask, 1);

  WiFi.mode(WIFI_STA);
  esp_now_init();
}

void loop() {
  // 1. Read PRAHARI Payload
  float rawNH3 = analogRead(PIN_NH3_ADC);
  txData.nh3_ppm = (rawNH3 / 4095.0) * 300.0;
  bool chemAnomaly = (txData.nh3_ppm > 50.0);
  txData.metal_present = (digitalRead(PIN_METAL_SENS) == LOW);

  // 2. Coincidence Matrix Classification
  if (chemAnomaly && txData.metal_present) {
    txData.threat_stage = 3; // MULTI-VECTOR VERIFIED THREAT
    digitalWrite(PIN_LED_RED, HIGH); digitalWrite(PIN_LED_GREEN, LOW);
  } else {
    txData.threat_stage = 0; // CLEAR
    digitalWrite(PIN_LED_RED, LOW); digitalWrite(PIN_LED_GREEN, HIGH);
  }

  // 3. Broadcast Telemetry over ESP-NOW
  esp_now_send(remoteAddress, (uint8_t *) &txData, sizeof(txData));
  delay(100); 
}
